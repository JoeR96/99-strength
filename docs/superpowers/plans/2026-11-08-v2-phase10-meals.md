# v2 Phase 10 — Meals and shopping list Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Pick this week's meals from a small cut-friendly recipe set, generate one de-duplicated shopping list with summed quantities, tick items off on the phone, and export it as text, share sheet or CSV.

**Architecture:** Two aggregates beside the plan: `Meal` (structured ingredients) and `ShoppingList` (items with `checked` and source meals). A pure Domain `ShoppingListGenerator` normalises ingredient names (trim, lower-case, singular-ish) and sums quantities per (name, unit). The ten recipes from CooksAssistant's `feature/import-to-bdtv-factory` branch are shipped as `meals-seed.json` with ingredients parsed **by hand once** into `{ name, quantity, unit }`; the seeder upserts them per user on first visit. CooksAssistant itself is never read or modified at runtime.

**Tech Stack:** as Phase 3 (Domain/Application/EF/API) + React pages under `features/meals`; `JsonColumn` for ingredient and item lists.

**Spec:** `docs/v2/brief.md` (Meals bullet in the research section) and `docs/v2/plan.md` → Phase 10; source material `docs/v2/source/cooks-assistant-recipes.ts` (11 `SeedRecipe` entries; the plan says "ten" — all 11 are included) and CooksAssistant's `components/shopping-list-export.tsx` (copy via `navigator.clipboard.writeText`, share via `navigator.share` with clipboard fallback).

## Global Constraints

- **No migration in the PR**; integrator scaffolds `AddMeals`. DbSets + configurations only; value-object lists via `JsonColumn`.
- Ingredient quantities are decimals with units from a closed set `{ g, kg, ml, l, tbsp, tsp, piece, clove, slice, handful, pinch }`; free-text ingredients that cannot be quantified keep `quantity = null, unit = null` and are never summed, only de-duplicated.
- Normalisation: trim, collapse spaces, lower-case, strip a trailing "s" only when the singular is in the seed vocabulary (so "eggs" → "egg" but "oats" stays).
- Export CSV header exactly `name,quantity,unit,checked`; text export one line per item `- [x] 2 clove garlic`.
- Every date is `DateOnly` from `ILocalClock`; week = Monday–Sunday.

## Review Focus

1. Two meals both needing garlic ("2 cloves garlic, minced" and "4 cloves garlic") produce one line `6 clove garlic`. Pinned in `ShoppingListGeneratorTests`.
2. Same ingredient in different units (200 g orzo and 1 handful spinach vs "a handful of baby spinach") stays as separate lines; never converts units. Pinned there too.
3. Regenerating the list for the same week keeps items already ticked when the same (name, unit) is still present. Pinned in `GenerateShoppingListHandlerTests`.
4. A planned meal removed mid-week drops its ingredients from the next regeneration but never from the already-ticked history. Pinned in the same handler tests.
5. CSV with a comma in an ingredient name is quoted correctly. Pinned in `ShoppingListExportTests`.

### Task 10.2: Seed
Files: `src/A2S.Infrastructure/SeedData/meals-seed.json` (embedded) — the 11 CooksAssistant recipes with ingredients hand-parsed, e.g. `"200g orzo"` → `{ "name": "orzo", "quantity": 200, "unit": "g" }`, `"2 cloves garlic, minced"` → `{ "name": "garlic", "quantity": 2, "unit": "clove" }`, `"salt, pepper, fresh parsley"` → three unquantified items; `MealSeeder.EnsureForUserAsync(userId)` upserts by `ExternalKey` (idempotent; called by `GetMealsQuery` when the user has none).
