# v2 Phase 7 — Suggested plan seed and onboarding Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One tap on first run creates the complete "Cut to 85 — Nov 2026" plan from the brief: A2S2 workout with the four lifting days and accessories, Mobility A/B, the three cardio protocols, the five habits, phases, checkpoints and caps; the only inputs are four training maxes and a start weight.

**Architecture:** A pure Domain/Application builder `SuggestedPlans.CutTo85Nov2026` returns a `SuggestedPlanSpec` (data only); `StartSuggestedPlanCommand` turns it into real aggregates in one unit of work (CreateWorkout → CardioProtocols → MobilityRoutines → Habits → TrainingPlan linked to the workout → Activate). Missing library exercises are added by an additive data migration so `CreateWorkout` resolves every template name. Onboarding is a first-run card on Today with the five inputs.

**Tech Stack:** as Phase 3; frontend React + TanStack Query for the onboarding card.

**Spec:** `docs/v2/brief.md` § 5 (every table and bullet is a test row); `docs/v2/plan.md` → Phase 7.

## Global Constraints

- Line-by-line fidelity to brief § 5: a table-driven test compares the spec to the brief's values; any deviation is a test failure, not a judgement call.
- Start date = `LocalDates.ComingMonday(today)`; nothing is Missed before it (Review Focus 5 of the phase plan).
- Session time estimate ≤ 55 min for each lifting day with `RestDefaults`; volume caps not exceeded by the seed itself (tests assert both).
- Units kg only. Start weight default 95 kg.
- The seed is **editable after starting**: nothing in it is special-cased by the UI.

## Review Focus

1. Starting on a Wednesday → start Monday, Today shows "starts Monday" and no Missed badges. Pinned in `StartSuggestedPlanHandlerTests`.
2. Starting twice (double tap, or a second device) creates one plan and one workout: the command is idempotent per user while an active suggested plan exists. Pinned in handler tests.
3. The "no 4×4 the day before Lower A or B" rule: the default schedule satisfies it (Wed 4×4 before Thu Upper B is fine); editing the schedule to put 4×4 on Monday yields a warning, not a block. Pinned in `PlanScheduleRulesTests`.
4. Mobility A is auto-counted on lifting days: completing Mon Upper A also marks the "Mobility A done" habit for that date. Pinned in `CompleteSession` → habit tick integration test.
5. Checkpoint pace on day one: 95 kg start, trend 95 → `OnPace`. Pinned in seed tests.

### Task 7.2: `SuggestedPlanSpec` and `CutTo85Nov2026`

**Files:** `src/A2S.Application/SuggestedPlans/SuggestedPlanSpec.cs`, `CutTo85Nov2026.cs`.
**Interfaces:** `record SuggestedPlanSpec(string Name, ProgramVariant Variant, IReadOnlyList<CreateExerciseRequest> Exercises /*TM placeholders filled by inputs*/, IReadOnlyList<ScheduledSessionSpec> Schedule, IReadOnlyList<(int a,int b, DayNumber day)> Supersets, MobilitySpec MobilityA, MobilitySpec MobilityB, CardioSpec[] Cardio, HabitSpec[] Habits, PhaseSpec[] Phases, CheckpointSpec[] Checkpoints, VolumeCaps Caps, WeeklyAllowances Allowances)`.
`CutTo85Nov2026.Build(SuggestedPlanInputs inputs)` where `SuggestedPlanInputs(decimal BenchTm, decimal SquatTm, decimal OhpTm, decimal DeadliftTm, decimal StartWeightKg = 95, DateOnly Today)`:
- Schedule: Mon Lift Day1 "Upper A"; Tue Lift Day2 "Lower A"; Wed Cardio 4×4 + Mobility B; Thu Lift Day3 "Upper B"; Fri Lift Day4 "Lower B"; Sat Cardio (C25K W1, LISS fallback noted); Sun Rest "walk only".
- Exercises per the brief with progression: main lifts Linear (TM from inputs, AMRAP on); accessories RepsPerSet with rep ranges 8–10 / 8 / 10 / 15 as written; unilateral flags with `IsUnilateral = true` for per-side moves; "extra set left" and "start left" expressed via `SideBias` notes on the plan session (`AccessoryNotes` dictionary keyed by exercise name) because `Exercise` has no side field.
- Supersets: Upper A (cable row, face pulls); Lower A (side plank, Pallof); Upper B (Meadows row, wall slides); Lower B (Copenhagen, dead bug).
- Mobility A and B drill lists verbatim from brief § 5 with standing alternatives.
- Cardio: `NorwegianFourByFour`, `CouchToFiveK(1)`, `Liss(35)`.
- Habits: Water 6/4 bottles; Walks 2/1; Morning weigh-in Numeric; Mobility A done Checkbox; Creatine Checkbox (+ Standing desk 4/2 when imported from Terran — not part of the seed).
- Phases: Cut from start to 21 Dec 2026; Maintenance 22 Dec 2026 – 3 Jan 2027; Cut 4 Jan – 8 Mar 2027.
- Checkpoints: 7 Dec 2026 92; 21 Dec 2026 91; 1 Feb 2027 88; 8 Mar 2027 85.
- Caps `VolumeCaps.Default`; allowances 1 flexible meal, 1 alcohol.
Tests: table-driven over every brief row; estimate ≤ 55 per day; caps not exceeded; non-Monday start.

### Task 7.3: `StartSuggestedPlanCommand`

Handler creates everything in order inside `IUnitOfWork`, links the workout, activates the plan, returns `StartSuggestedPlanResult(Guid PlanId, Guid WorkoutId, DateOnly StartDate)`. Idempotent: if the user already has an active plan named the same, return it. Endpoint `POST /api/v1/plans/suggested/cut-to-85` body `{ benchTm, squatTm, ohpTm, deadliftTm, startWeightKg }`; `GET /api/v1/plans/suggested` lists available seeds with their preview (schedule + inputs needed).
Tests: handler creates 1 plan/1 workout/5 habits/3 protocols/2 routines; double start idempotent; validation (TMs 20–400 kg).
