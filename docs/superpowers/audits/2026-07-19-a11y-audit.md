## Violations by rule (before), ordered critical → serious

### CRITICAL

#### `label` — form field has no programmatic label (11 nodes: /simulate, edit-exercises modal) — FIXED
Number inputs whose visible `<label>`/`<Label>` text was adjacent-but-unassociated (no `htmlFor`/`id`). axe cannot tie the text to the control.
- **Fix (attribute-level, no DOM change):** added `aria-label` to each control.
  - `features/workout/ExerciseEditRow.tsx` — compact weight/TM `Input` → ``aria-label={`${TM|Weight} for ${state.name}`}``
  - `features/workout/SimulationPage.tsx` — Sessions / Days / Success % / Maintain % inputs → `aria-label`

#### `select-name` — select has no accessible name (1 node: /simulate) — FIXED
- `features/workout/SimulationPage.tsx` workout picker `<select>` → `aria-label="Workout"`.

#### `button-name` — button has no discernible text (1 node: /hevy) — FIXED
Icon-only show/hide-API-key ghost button.
- `components/hevy/HevySettings.tsx` → ``aria-label={showKey ? 'Hide API key' : 'Show API key'}``.

#### `link-in-text-block` — link distinguished only by colour (1 node: /hevy) — FIXED
"Hevy Pro subscription" / "Hevy Settings" links used `hover:underline` (no resting non-colour cue).
- `components/hevy/HevySettings.tsx` → `underline` (always on).

#### `scrollable-region-focusable` — scrollable region not keyboard-focusable (1 node: /setup) — **DEFERRED**
The `SetupWizard` step-indicator strip (`div ... overflow-x-auto`) scrolls but has no `tabindex`/`role`, so keyboard-only users can't scroll it. **Recorded, not fixed:** this needs a focusable-region / keyboard affordance decision (structural), which is out of the class/attribute-only scope for this pass. axe rule id: `scrollable-region-focusable`. File: `features/workout/SetupWizard.tsx` (the `max-w-md mx-auto overflow-x-auto` step row).

## Deferred / recorded (not fixed this pass)

- **`scrollable-region-focusable` @ /setup** — as above; structural keyboard fix.
- **Neon categorical palette vs AA** — `lib/muscleGroupStyles.ts` badges are a *sanctioned* fixed categorical palette (see `src/AGENTS.md`). This pass hardened the **text** colour (mix toward foreground) so all current badges pass AA while keeping hue identity; the underlying `--color-neon-*` tokens (shared with charts) were **not** altered. If future muscle groups map to a low-luminance neon at small size, re-verify.
- **White-on-`bg-destructive` buttons** — `--color-destructive-foreground` was left white. No such button rendered in this sweep, but white-on-destructive is ~3.5:1. If a solid destructive button is added, switch its foreground to a dark token (mirrors the primary fix).
- **`SetupWizard.tsx` / `SimulationPage.tsx` over-500-line split** — pre-existing debt (see `src/AGENTS.md`), untouched.
